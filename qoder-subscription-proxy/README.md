# 订阅代理管理 · Qoder 使用指南

这个插件专为 **Qoder Desktop** 提供本机模型代理。你在 Magpie 里登录自己的订阅账号或配置服务商，然后就能在 Qoder 中选择该账号有权使用的模型。插件版本 **2.0.1**。管理页会显示这台电脑正在使用的 Magpie 核心版本。

**代理跟着 Qoder 启停。** 插件启用后，打开 Qoder 并连接插件，代理就会启动；完全退出 Qoder 后，它托管的代理也会停止。只关闭管理页标签或原生管理页的浏览器窗口，当前代理可以继续工作。如果你要让 Qoder、其他编辑器和命令行工具长期共用模型，推荐[单独运行 Magpie](https://github.com/yetone/magpie)，再把各工具接到独立实例的地址。这样即使关掉 Qoder，其他工具也能继续使用。

## 第一步：安装，等核心就绪

1. 在 Qoder 安装并启用「订阅代理管理」。如果拿到的是 ZIP，进入 **扩展 → 插件 → 添加插件 → 上传插件 ZIP**，选择 `qoder-subscription-proxy-v2.0.1.zip`。无需解压，也无需选平台。支持 Windows x64、macOS x64 / ARM64、Linux x64 / ARM64。
2. 确认插件提供的 MCP 服务已连接。首次连接会优先复用本机已经校验的核心。全新安装会从 Magpie 官方 Release 下载当前平台的最新稳定版，校验后保存在本机。实际大小以页面显示为准。
3. 点击 **更多 → 订阅代理管理**。下载期间能看到已接收大小、百分比和校验、安装阶段。看到 **核心已就绪** 后，点击 **打开原生管理页（浏览器）**。

如果以前主动停止过代理，插件会记住这个选择。在管理页点 **启动核心** 即可恢复。打开管理页、下载核心都无需先配置聊天模型。

## 第二步：在 Magpie 准备账号和模型

- **已有服务商 API Key**：在 Magpie 原生管理页的「供应商」添加自己的服务商，按提示填写它提供的 API Key。
- **要用自己的订阅账号**：进入 **设置 → 隐私 → 订阅账号**，按服务商提示本人登录。托管核心使用插件私有主目录；该选项可能让上游尝试读取操作系统凭据存储中的其他客户端条目，不能视作账号沙箱，不需要订阅时可保持关闭。
- 服务商需要额外插件时，在 Magpie 的插件管理页面自行安装，然后完成该服务商要求的配置或登录。

打开 Magpie 的模型目录，选一个账号有权限使用的模型。**下一步任选一种接入方法即可。** 服务商密钥填在 Magpie；Qoder 连接的是本机代理。

## 第三步：让 Qoder 使用模型

### 让 Magpie 识别并接入 Qoder 与其他已安装客户端

默认会自动识别这台电脑上已安装的客户端，并把它们的真实配置目录交给 Magpie 的 Agent 页面：Qoder / Qoder CN（按构建自动判断）、Codex、Claude Code、Copilot CLI、Cline、Cursor、Qwen、Kimi、Grok、OpenClaw、Ante、OpenCode、Pi 和 Zed。未列出的客户端仍只会看到插件私有目录；宿主的服务商密钥、URL 和行为变量不会传给核心。账号发现沿用 Magpie 原生设置，新安装由插件默认关闭，已有设置保持原样；订阅账号需在 Magpie 中显式开启。上游接入或迁移客户端时可能改写该客户端的模型设置；列出和识别本身不会主动改写模型设置。若另一套 Magpie 已管理同一个客户端，建议使用下方的手动配置，避免两套实例同时改写。

需要固定只开放一个 Qoder 构建时，可在启动 Qoder 的操作系统用户环境中设置 `BRIDGE_QODER_CLIENT=qoder`（国际版）或 `BRIDGE_QODER_CLIENT=qoder-cn`（中国版），完全退出并重开 Qoder 后再启动核心。显式选择只开放选中的构建；未设置时插件自动识别宿主上实际安装的构建。Qoder 会把两个变量同时指向当前构建的目录，插件只暴露与目录名一致的一个入口，避免两个 Agent 入口写同一份设置。

1. 在 **Magpie 原生管理页 → Agent** 找到识别到的 **Qoder**、**Qoder CN** 或其他客户端。这里的「Agent」是 Magpie 的客户端配置页面。
2. 打开该客户端的 **将 Qoder 接入 magpie** 开关（中国版选对应项），在模型选项里选择刚才准备好的模型。Magpie 会把本机代理地址、供应商和所选模型写入对应客户端在宿主上的用户设置。
3. 回到 Qoder，**新建一个会话**，确认所选模型后发一句简单的问题。已打开的旧会话会继续使用它原来的模型。

想撤销自动接入，可在同一 Agent 页断开 Qoder，让 Magpie 尝试恢复接入前记录的模型。自动接入需要当前 Qoder 账号支持使用自定义供应商（BYOK）。[Magpie 的 Qoder 适配实现](https://github.com/yetone/magpie/blob/v0.1.4597/internal/agent/qoder.go)

### 推荐：在 Qoder 手动添加自定义模型

如果希望自己选字段，在 **Qoder → 设置 → 模型 → 添加模型 → 供应商 → 自定义** 中选择 **OpenAI Compatible**，然后选择 **Chat Completions API**。

| Qoder 中的字段 | 怎么填 |
| --- | --- |
| 接口地址（Base URL） | `http://127.0.0.1:19787/v1`。如果改过端口，复制插件管理页显示的「模型端点」。 |
| API Key | 填 `qoder-local` 即可。这是本机客户端标识，服务商密钥和浏览器管理密钥都不要填在这里。 |
| Model ID | 从 Magpie 模型目录原样复制完整 ID，保留其中的 `/` 和前缀。可添加多个 Model ID。 |
| 显示名称及能力 | 名称可以自己取。按模型实际支持情况填写上下文、视觉和思考能力。 |

点击 **校验并添加模型**，在新会话的模型选择器中选中它，发送一条消息验证。`19787` 是模型服务端口；`19788` 是浏览器管理端口。[Qoder 自定义模型官方说明](https://docs.qoder.com/zh/qoder/custom-models.md)

国际版默认使用 `~/.qoder/settings.json`，中国版使用 `~/.qoder-cn/settings.json`。指定了 `QODER_CONFIG_DIR` 或 `QODERCN_CONFIG_DIR` 时，编辑对应目录下的 `settings.json`。先保留原配置，把下面的 `local-magpie` 项合并到已有的 `providers`，并把 `name` 合并到已有的 `model`。保留其他字段。将每个 `【实际模型ID】` 替换成同一个、从 Magpie 复制的完整值。

```json
{
  "providers": {
    "local-magpie": {
      "displayName": "本机 Magpie",
      "protocol": "openai",
      "baseUrl": "http://127.0.0.1:19787/v1",
      "apiKey": "qoder-local",
      "model": "【实际模型ID】",
      "models": [{ "model": "【实际模型ID】", "displayName": "我的模型" }]
    }
  },
  "model": { "name": "local-magpie/【实际模型ID】" }
}
```

`local-magpie` 是这个示例给 Qoder 供应商取的名字，只用在 `model.name` 的最前面。保存后新建 Qoder 会话验证。需要自动同步模型清单和能力时，使用上面的 Agent 方法。

## 修改本机端口

在 **更多 → 订阅代理管理 → 端口设置** 中分别填写「模型端口」和「浏览器管理端口」。默认是 **19787** 和 **19788**。选择两个不同、未被占用的端口，范围为 `1` 到 `65535`。等正在生成的回复结束后再点 **保存并应用**，运行中的代理会短暂重启。

改了模型端口后，手动配置的客户端需要把 Base URL 改为页面显示的新模型端点；使用 Agent 自动配置的，可以回 Magpie 的 Agent 页重新同步配置。改了管理端口后，从插件页面重新点「打开原生管理页（浏览器）」。如果某项标记为由环境变量指定，修改对应的 `BRIDGE_PORT` 或 `BRIDGE_MANAGEMENT_PORT` 并重连插件即可。

## 遇到问题时看哪里

先打开 **更多 → 订阅代理管理**。页面显示的是当前下载和运行状态。展开「配置与使用详情」可查看模型样例及本机数据目录，再按显示的原因处理。

| 你看到的情况 | 可以怎么做 |
| --- | --- |
| 下载失败、超时或 SHA256 不匹配 | 确认可访问 Magpie 的 GitHub Release，检查系统代理或 `QODER_HTTP_PROXY`，再点「重试启动」。校验失败的文件不会执行。 |
| 端口被占用 | 检查是否另开了 Magpie 或另一套代理。选择要保留的实例；需要并行运行时，给两套服务分配不同的模型端口和管理端口。 |
| 本地配置错误、核心路径或权限异常 | 按页面提示检查对应字段或目录。修改环境变量后请重连插件 MCP；修复本地文件后可点「重试启动」。 |
| 核心已就绪，模型仍不可用 | 检查 Magpie 中的账号、权限、额度和模型 ID，再用新会话测试。核心就绪只说明本机服务可用。 |
| 浏览器原生管理页要求重新登录 | 核心重启后回到插件页面，再点一次「打开原生管理页（浏览器）」。每次启动都会生成新的管理登录凭据。 |
| 退出 Qoder 后，其他工具也连接失败 | 需要共用时单独启动 Magpie，并把其他工具的 Base URL 改成独立实例的实际地址。 |

## 升级、停用及高级选项

**Magpie 会自动更新吗？** 独立版 Magpie 可以定时检查更新（默认每 6 小时），并可选择仅通知或自动下载。独立桌面版如果还打开自动重启，会等正在处理的请求结束，再重启应用更新。插件用自己的版本管理页处理更新，请保留原生更新选项的现有设置。首次启动会优先使用本机已校验的核心；全新安装会查询 Magpie 官方最新稳定版，按平台下载。之后每次打开插件管理页都会检查更新，发现新版只提示，由你决定是否更新。

**下载和切换分两步。** 点「下载更新」后，旧版继续为现有请求服务。页面显示新版的下载进度，校验通过后可以选「稍后切换」。准备好时先等正在生成的回复结束，再点「切换版本」并确认，代理会短暂重启。重新打开 Qoder 会继续使用上次选定的版本。

需要某个特定版本时，在「Magpie 更新」的「指定版本」输入官方版本号（例如 `0.1.4582` 或 `v0.1.4582`），点「下载指定版本」。插件会验证此版本有适合你电脑的官方文件，下载完成后可以稍后再切换。

在「已安装版本」可以看到各版本和占用空间，切换回已保留的旧版，或点对应行的「删除」清理闲置核心。删除前会显示版本号供确认，账号和模型设置保留。当前使用的版本须先切换到其他版本才能删除。[Magpie 更新选项](https://github.com/yetone/magpie/blob/v0.1.4584/internal/cli/update_auto_cli_test.go)

从 1.x 升级前，先等正在生成的请求结束，用旧版插件调用 `bridge_stop`，再关闭共享该数据目录的旧 MCP 会话。随后升级插件并重新连接。2.0 会拒绝接管旧版仍在运行的核心。暂停状态跨重连保留，点 **启动核心** 或调用 `bridge_start` 恢复。此前使用其他核心的用户需要在 Magpie 中重新登录；插件保留原有数据，不会替你迁移旧授权。

| 工具 | 用途 |
| --- | --- |
| `bridge_status` | 查询下载、缓存、启动诊断和模型服务状态。不支持管理页的宿主也可以调用。 |
| `bridge_start` / `bridge_stop` | 显式启动、重试，或持久暂停代理。 |
| `bridge_open_management` | 用默认浏览器打开 Magpie 原生管理页。 |
| `image_gen_gpt` | 调用已配置且支持生图的 GPT 模型，图片保存到本机；有多个候选时可选择模型。 |

默认数据目录为 `~/.qoder/qoder-subscription-proxy/data`，由本插件独占，升级插件时继续使用。`magpie/` 保存本实例的设置和授权，`home/` 是托管核心的用户主目录，`cache/` 和 `state/` 保存缓存与状态，`runtimes/` 缓存核心，`generated/` 保存图片。模型和管理端口都与独立 Magpie 错开后，两套服务可以同时运行。`BRIDGE_DATA_DIR` 可指定其他数据目录。`BRIDGE_PORT` 和 `BRIDGE_MANAGEMENT_PORT` 分别设置模型端口和管理端口；`BRIDGE_BIN` 可指向已准备好且具有执行权限的兼容核心，插件接到这个设置后会跳过下载。使用自定义核心时，请放在独立程序目录，旁边不要有 `data` 或 `.portable`。托管核心只接收运行所需的环境变量；宿主环境中的服务商密钥不会传给核心，请在本插件的原生管理页中填写。为便于识别和接入，宿主上已存在的常见客户端配置目录（见上文 Agent 说明）会交给核心，其余宿主目录和密钥仍保持隔离；`BRIDGE_QODER_CLIENT` 可显式固定一个 Qoder 构建。

代理仅供 `127.0.0.1` 本机使用。不要将端口映射到公网，也不要分享浏览器登录链接、Cookie、`launcher-secrets.json` 或未经脱敏的日志。卸载插件会保留本地数据；如需撤销订阅授权，请在服务商账号中操作。
